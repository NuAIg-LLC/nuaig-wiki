Organisations increasingly want to let an assistant or an automation read from their
systems. The platform has a position on this, and it is the same position it has on
everything else: **a machine is held to the same rules as a person, and never to fewer.**

## The principles

<ol class="steps not-content">
  <li>
    <h4>Never more than a person</h4>
    <p>The same role-to-scope rules, the same community membership requirement, the same minimum-necessary masks, and the same audit. A tool that asks for something its person may not read gets the same refusal.</p>
  </li>
  <li>
    <h4>Read-mostly</h4>
    <p>The surface is designed around reading. A tool that can summarise a case does not need to be able to decide one, and no tool can record a decision.</p>
  </li>
  <li>
    <h4>Credentials are validated properly</h4>
    <p>The issuer and audience are checked exactly. A credential minted for some other purpose is refused.</p>
  </li>
  <li>
    <h4>Never forward a credential</h4>
    <p>When a tool call needs another service, the platform acts as its own client for that service. It does not hand the caller's credential onward, which would let any downstream service impersonate the caller.</p>
  </li>
  <li>
    <h4>The assistant still cannot decide</h4>
    <p>Giving an AI client read access changes who can see a case. It does not change who can decide one. See <a href="/model/ai-boundary/">Where AI starts and stops</a>.</p>
  </li>
</ol>

## Why it is off by default

Programmatic access that reaches records and is deployed, but that nobody reviews because
nobody uses it, is a worse position than not having it. So the capability is not part of a
standard deployment. An organisation that wants it asks for it, and it is then reviewed like
any other access path: which people may use it, which tools it exposes, and what audit it
produces.

## What to ask before enabling it

<div class="defs not-content">
  <div><dt>Who is the tool acting for?</dt><dd>A named person's authority, or a service identity with deliberately narrow scopes. "Everything" is not an answer.</dd></div>
  <div><dt>Which communities?</dt><dd>Membership still applies. A tool acting for someone sees only the buildings that person belongs to.</dd></div>
  <div><dt>What can leave the organisation?</dt><dd>Anything a tool reads may be passed to a model. That is a data-protection decision for the client, made with the same care as sending the data anywhere else.</dd></div>
  <div><dt>What will be audited?</dt><dd>Every read is recorded with the actor and the fields touched, so a tool's reads are as visible as a person's.</dd></div>
</div>
